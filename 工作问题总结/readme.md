# https 环境下嵌套使用 http 会被浏览器阻止，怎么解决？

1. 配置代理服务器把 http 代理成 https 请求，实际还是 http 请求
2. 使用沙盒，利用 a 标签或 window.open 打开新窗口
3. 升级目标服务器为 https
4. 禁用浏览器不让混合的机制
5. CSP

```
<meta http-equiv="Content-Security-Policy" content="upgrade-insecure-requests; default-src https: http://10.0.188.138:10807;">
```

- upgrade-insecure-requests：将所有 HTTP 请求自动升级为 HTTPS。
- default-src：指定允许加载的资源来源。

6. 如果目标 HTTP 内容是静态的（如 HTML 表格），可以将其下载并托管到 HTTPS 环境中。

# 流式输出显示原始markdown内容如何解决？

1. 采用Cherry-Markdown+prompt限制+后端分片规则约束
   输出Markdown表格规则：
   1. 表格必须连续输出，表头、分隔线、数据行之间不插入换行、多余文字；
   2. 禁止把单行表格切分成多段输出；
   3. 表格结构完整后再输出后续文本；
      不要零散输出表格片段。

### Cherry-Markdown

如果在长对话中prompt规范被遗忘？

1. 动态重注入：当对话次数达到某个阈值就在用户的输入中追加。
2. 自动监测用户的提问是否跟表格有关，有关再追加
3. 压缩上下文，对于System Role绝不压缩

#### 工作原理

1. 普通解析器工作模式：
   缓冲区全文 → 一次性全量语法解析 → 生成 AST → 渲染 HTML
   只要语法片段不合法，直接识别为普通文本。
2. Cherry Stream 新增一层增量预解析层：
   持续监听追加的文本 chunk，持续扫描行首正则：
   /^\|.\*\|/ → 判定疑似表格起始行
   一旦命中疑似表头，执行 3 个关键动作：
   在内存虚拟 AST 中临时补全缺失的表格分隔线节点（内存虚拟节点，不会写入原始 markdown 文本）；
   构建一个未闭合的临时表格容器 DOM；
   后续持续流入的以|开头的行，持续追加到这个临时表格内部。

3. 动态校验与降级机制（非常关键）
   两种情况：
   ✅ 后续收到真正的 |---| 分隔行
   → 虚拟补丁和真实语法重合，表格持续正常渲染，无闪烁。
   ❌ 长时间没有收到表格分隔行（超时阈值内部默认约 800ms）
   → Cherry 判定：这不是表格，只是一堆带竖线普通文本；
   → 销毁临时表格 DOM，降级渲染为普通文本。
   这就是为什么极端场景下依然会轻微闪一下，不是万能兜底。
4. 补充：它不会做的事情（很多人误解）
   ❌ 不会阻塞渲染、不会缓存等待完整表格，不存在 “攒齐表格再展示”；
   ❌ 不会修改原始 buffer 文本，不会自动补全用户 / 模型输出的 markdown 字符串；
   ❌ 不能预测跨大片无关文本之后才出现的表格分隔线；
   如果模型输出：
   plaintext
   |名称|金额
   随便一段无关解释文字
   |---|---|
   中间隔断太久，预渲染表格会超时销毁，依然会出现闪烁。

5. 检测 buffer 末尾是否存在未闭合表格疑似行（以|开头，没有匹配到表格分隔行）
   → 增加300~600ms 渲染防抖
